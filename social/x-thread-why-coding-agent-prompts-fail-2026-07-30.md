## Tweet 1 — Hook

A better prompt can rescue one coding-agent task. It cannot teach the repository.

If every fresh session needs the same warning, command, boundary, or architecture note, that context should be versioned beside the code—not pasted into another prompt.

**X-weighted count:** 251 / 280

## Tweet 2 — Key takeaway

Use prompts for the current outcome, acceptance criteria, and authority. Use repository context for maps, validation commands, generated-file rules, decisions, and handoff evidence.

The durability test: can a fresh session succeed without replaying private prompt history?

**X-weighted count:** 273 / 280

## Tweet 3 — Repository CTA

Repeated prompt corrections should become repository memory: name the decision, place the rule at the narrowest scope, validate it, then rerun the task in a fresh session.
